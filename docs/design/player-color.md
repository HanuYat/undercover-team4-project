# 플레이어 로봇 색 (#432)

플레이어가 자기 로봇을 **머리·상체·하체** 세 부위로 나눠 칠한다. **순수 코스메틱** — 식별·게임플레이 기능이 아니다.

## 1. 왜 부위를 메시로 나눴나

Synty 로봇(`SM_Gen_Chr_Robot_01`)은 **스킨드 메시 1개·서브메시 1개**라 원래 몸 전체가 한 색이다. 부위별로 칠하려면 셋 중 하나가 필요했다.

| 방법 | 판정 |
|---|---|
| 셰이더의 마스크 슬롯(`_Skin_Mask`/`_Hair_Mask`) 사용 | **불가** — 로봇에는 마스크가 안 물려 있고, 새로 그려도 소용없다. 이 모델의 UV가 아틀라스의 좁은 영역(x 0.004~0.251)에 몰려 있다 = **UV 섬을 부위끼리 재사용**한다. UV 공간에서 머리와 다리를 가를 수 없다 |
| 커스텀 셰이더 + 정점 속성에 부위 인덱스 | 가능하지만 Synty 룩을 손으로 재현해야 한다 |
| **서브메시 3개로 분할 (채택)** | 본 가중치로 삼각형을 나눠 담고 `SetPropertyBlock(block, materialIndex)`로 슬롯마다 다른 `_BaseColor`. **셰이더는 Synty 것 그대로** |

부위 판정은 주 가중치 본 이름으로 한다 — `Head`/`Neck`/`Eye`/`Jaw`는 머리, `Hips`/`UpperLeg`/`LowerLeg`/`Ankle`/`Ball`은 하체, 나머지(척추·어깨·팔·손)는 상체. 삼각형은 정점 셋의 다수결로 정하므로 경계에서 한 조각이 옆 부위로 넘어가도 눈에 띄지 않는다.

비용: 몸 하나당 드로우콜이 1 → 3. 플레이어 최대 6인이라 문제되는 규모가 아니고, NPC는 손대지 않았다.

## 2. 메시 다시 굽기

`Tools > Undercover > 로봇 부위 메시 굽기 (#432)` → `Assets/Meshes/SM_Gen_Chr_Robot_01_Parts.asset` 생성.

⚠ **결과물은 원본과 끊긴 사본이다.** 다음 경우에 **직접 다시 돌려야 한다** — 안 돌려도 에러가 나지 않고 옛 메시가 조용히 그대로 쓰인다:

- Synty 패키지를 업데이트해 원본 메시가 바뀌었을 때
- 플레이어 모델을 다른 것으로 바꿀 때 (`RobotPartMeshBaker`의 원본 경로도 함께 고칠 것)

다시 구운 뒤에는 `Player.prefab`의 **몸·시체 렌더러 두 개**가 새 메시를 물고 머티리얼 슬롯이 3개인지 확인한다. 초상 무대용 `Assets/Prefabs/UI/RobotPreview.prefab`도 같은 메시를 쓴다.

## 3. 값이 오가는 길

색은 **팔레트 인덱스**로만 오간다 (`PlayerColorSet` = 3바이트). 팔레트(`PlayerColorPalette`)가 정본이라 대역폭이 작고, 범위 밖 값은 팔레트가 자르므로 어느 피어에서든 같은 색이 나온다.

```
GameSettings.PlayerColor{Head,Torso,Legs}   ← 값의 출처 (PlayerPrefs, 로컬)
        │
        ├─ 로비: SessionRoster (LobbyPlayerEntry.Colors) → 명단 카드 얼굴
        └─ 게임 씬: PlayerCosmetics (오너 쓰기 NetworkVariable) → 몸·시체·1인칭 팔
```

두 경로는 **씬이 겹치지 않아** 동시에 살아 있지 않다(로비 명부는 로비에서만, 플레이어 오브젝트는 게임 씬에서만). 이중 출처가 아니라 씬마다 존재하는 유일한 운반 수단이다 — 음소거(#430)와 같은 구조다.

- **팔레트 순서를 배포 후 중간에 바꾸지 말 것.** 인덱스가 곧 저장·동기화 값이라 뒤 항목이 밀리면 예전에 고른 색이 달라진다. 추가는 항상 끝에.
- 서버는 값을 검증하지 않는다 — 순수 코스메틱이라 틀린 값이 와도 자기 로봇 색만 이상해진다.

## 4. 칠하기는 BodyTint 하나가 맡는다

`_BaseColor` 오버라이드의 단일 소유자는 `BodyTint`(#478)다. 채널 우선순위는 **flash > sustained > base**이고 이번에 밑색(base)이 추가됐다 — 감전 발광(#477)이 끝나면 흰색이 아니라 **그 사람이 고른 색**으로 돌아온다. 코스메틱이 따로 프로퍼티 블록을 들었다면 연출이 걷힐 때 색까지 함께 지워졌을 것이다.

두 가지가 실제로 문제를 냈고 지금은 규칙으로 굳어 있다:

- **머티리얼이 하나뿐인 렌더러는 렌더러 단위로 민다.** NPC 몸 전부와 1인칭 팔이 여기 해당한다 — 서브메시 단위로만 밀었더니 NPC 감전 발광이 화면에 나오지 않았다.
- **밑색은 꺼진 렌더러에도 칠한다.** 시체 모델은 평시에 렌더러가 꺼져 있다가 죽을 때 켜지므로(`PlayerRagdoll`), 건너뛰면 죽는 순간 머티리얼 원색으로 나온다.

## 5. 얼굴은 색 조합 단위로 굽는다

로비 명단 카드의 얼굴은 `LobbyPortraitStage`가 무대 모델을 그 색으로 갈아입혀 굽는다. 사람이 아니라 **색 조합**이 열쇠라, 같은 색을 고른 두 사람은 그림 한 장을 나눠 쓴다.

- 굽고 난 뒤 **명부에 있는 색 + 내 색**만 남기고 나머지는 버린다 — 팔레트를 눌러 볼 때마다 조합이 하나씩 늘어 그대로 두면 텍스처가 세션 내내 쌓인다.
- 게임 씬(Tab 상황판)은 로비에서 구운 것을 그대로 쓴다. 게임 씬에서 다시 구우면 맵 조명을 타 어둡게 나온다 (#720).
- 카드는 얼굴 구도라 **머리 색만 보인다.** 상체·하체는 커스터마이징 창의 전신 미리보기에서 본다.
