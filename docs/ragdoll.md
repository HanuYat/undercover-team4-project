# 래그돌 — 현재 구조와 다루는 법

플레이어가 죽으면(`IncapacitationCause.Die`) 애니메이터를 끄고 뼈를 물리에 넘긴 뒤, 착지·정착하면
다시 애니메이터로 되돌린다. 폭발로 죽으면 여기에 **임펄스**가 붙어 날아간다.

> **이 문서는 "지금 어떻게 되어 있나"만 담는다.**
> 왜 그렇게 됐는지, 무엇을 시도했다 되돌렸는지는 [506-explosion-ragdoll.md](506-explosion-ragdoll.md)에
> 있다. 그쪽은 1300줄짜리 **작업 기록**이라 통독용이 아니다 — 아래에서 `§9-x`로 가리키는 항목만
> 찾아 읽으면 된다.

---

## 1. 구조 — 세 컴포넌트

전부 **Player 프리팹 루트**에 붙는다 (CharacterController·PlayerIncapacitation과 같은 오브젝트).

| 컴포넌트 | 위치 | 하는 일 |
|---|---|---|
| `RagdollRig` | `Common/Ragdoll/` | 뼈·스킨 수집, 키네마틱 토글, 임펄스, 감쇠, 속도캡, 포즈 캡처/복원, 블렌드 |
| `RagdollRope` | `Common/Ragdoll/` | 관절 밧줄 — 시체를 물리로 끌어온다 (#365 운반 / #398 드래그) |
| `PlayerRagdoll` | `Player/View/` | 상태 기계, 사망 폴링, 캡슐 추종, 원격 정렬, 정착 루트 포즈, 기상 블렌드 |

### 자른 선

**"뼈를 물리에 넘기는 것"(공통) vs "누가 위치를 쥐나"(제각각).**

앞의 둘에는 `IsOwner`·`NetworkObject`·`CharacterController`가 **한 번도 나오지 않는다.**
나오기 시작하면 분리가 무너진 것이다. NPC 래그돌은 이 둘을 그대로 쓰고 자기 프록시(NavMeshAgent)와
권위(서버)만 따로 쥔다. → [§8](#8-npc로-확장할-때)

상속이 아니라 **컴포지션**이다. 프록시와 권위가 둘 다 달라서 추상 베이스로 만들면 거의 전부
`abstract`가 되고 공유되는 실체가 남지 않는다.

## 2. 수명 주기

```
Animated ──진입(사망)──> Ragdoll ──정착──> Settled ──부활──> BlendingToAnimator ──> Animated
                          날아감          물리 유지          정착포즈 → 기상포즈
```

| 상태 | 뼈 | 캡슐(CharacterController) |
|---|---|---|
| `Animated` | 전부 키네마틱 (애니메이터가 포즈를 쥠) | 켜짐, 입력으로 이동 |
| `Ragdoll` | 전부 물리 + 임펄스 | **꺼짐**, 매 프레임 골반 위치 대입 |
| `Settled` | 전부 물리 (아무것도 안 붙듦) | 꺼짐, 골반 수평 + 지면 높이 |
| `BlendingToAnimator` | 전부 키네마틱 | 켜짐 |

**진입 경로는 둘인데 결과는 하나다.**

| 경로 | 무엇이 오나 | 임펄스 |
|---|---|---|
| 사망 폴링 (`PollDeath`) | `PlayerIncapacitation`의 NetworkVariable | 0 (그 자리에 무너짐) |
| 폭발 (`BombDevice`) | ClientRpc로 사망자 + 임펄스 | 서버가 계산한 값 |

**둘은 서로 다른 오브젝트에서 오므로 도착 순서가 보장되지 않는다.** 순서를 맞추려 들지 말고
어느 쪽이 먼저 와도 결과가 같게 만든다 — 그게 아래 불변식 4·5다.

## 3. 불변식 — 깨면 증상이 돌아온다

각 항목 뒤 `§`는 실제로 밟았던 기록이다.

1. **뼈를 동기화하지 않는다.** 각 피어가 로컬로 시뮬레이션하고, 궤적은 오너의 루트에서 받는다.
   따라서 **입력(임펄스)이 같아야 결과가 같다.** 실측으로 9m를 날고도 두 피어가 5cm 안에서 일치했다. `§10-3`

2. **캡슐은 매 프레임 골반을 따라간다** (`TickCapsuleFollow`). 스윕을 쓰지 않고 위치를 직접 대입한다 —
   대리값은 지형을 존중할 이유가 없다. 이걸 안 하면 정착 순간 캡슐이 한 번에 텔레포트하고,
   그 늦은 점프가 이 기능의 거의 모든 버그의 뿌리였다. `§9-4` `§9-6` `§10-0`

3. **정착은 아무것도 붙들지 않는다.** 골반을 캡슐에 용접하거나 스프링으로 매달면 몸이 찢어지거나
   허리가 땅에 박힌다. 끄는 것은 밧줄이 하고, 캡슐은 따라갈 뿐이다. `§9-7`

4. **폭발 임펄스는 서버가 계산해서 보낸다.** 각 피어가 직접 계산하면 감쇠식이 쓰는 대상 위치가
   NetworkTransform 보간값이라 피어마다 세기·방향이 갈린다. `§10-3`

5. **부활은 죽음을 본 뒤에만 성립한다.** "살아 있는데 래그돌이면 부활"은 원격에서 거짓이다 —
   임펄스가 사망 동기화보다 먼저 오면 방금 시작한 비행을 부활로 오인해 취소한다. `§9-19`

6. **밧줄 감쇠·속도캡은 밧줄의 수명 안에서만 건다.** 상시로 걸면 사망 직후의 탄도 비행이 같이 죽는다.
   거는 자리와 푸는 자리가 정확히 짝이어야 한다(`ApplyTuning` ↔ `Detach`). `§9-17`

7. **원격 정렬은 동력이 아니라 표류 방지다.** 상한을 올려 "끌어오게" 만들려던 시도가 발산으로 끝났다.
   몸을 움직이는 것은 각 피어의 로컬 물리다. `§9-16` `§10-5`

## 4. 튜닝 노브

### 날아가는 세기 — `BombDevice` (Bomb 프리팹)

| 필드 | 값 | 뜻 |
|---|---|---|
| `m_ragdollImpulseScale` | 0.22 | 넉백 수평 세기 × 이 값 = 시체 수평 속도 |
| `m_ragdollLiftRatio` | 1.2 | **곧 발사각.** 1.0이 45°로 사거리 최대. 크면 높이만 뜬다 |

⚠ **`PlayerRagdoll.m_flightAlignPullSpeed`(16)와 짝이다.** 임펄스를 올리면 그쪽도 올려야 원격이
시체를 따라잡는다.

### 밧줄 — `RagdollRope` (Player 프리팹)

| 필드 | 값 | 뜻 |
|---|---|---|
| `m_length` | 2 | 손↔골반 최대 거리. 길수록 장력이 덜 걸려 순해진다 |
| `m_limitSpring` | 1500 | 한계 **바깥에서만** 작동. 늘어져 있으면 힘이 0이다 |
| `m_limitDamper` | 1000 | **과감쇠로 둔다**(ζ≈1.5). 부족감쇠면 회전 시 에너지가 쌓인다 `§9-17` |
| `m_dragLinearDamping` | 0.6 | 밧줄이 늘어진 반주기의 **유일한** 에너지 배출구 |
| `m_dragAngularDamping` | 0.6 | 팽이처럼 도는 것을 잡는다 |
| `m_maxSpeed` | 8 | 슬링 차단 **하드 캡**. 감쇠로는 원리적으로 못 막는다 `§9-18` |

**Play 중 인스펙터에서 바꾸면 밧줄을 다시 잡지 않아도 바로 먹는다.**

### 정착·정렬 — `PlayerRagdoll`

| 필드 | 값 | 뜻 |
|---|---|---|
| `m_settleSpeedThreshold` / `HoldSeconds` / `TimeoutSeconds` | 0.15 / 0.3 / 5 | 언제 멈춘 것으로 볼지 |
| `m_groundProbeDistance` | 1.5 | 골반 밑 지면 탐색. **짧게 잡을 것** — 길면 얇은 바닥을 뚫고 아래층을 찾는다 |
| `m_rootYawOffset` | 0 | 기상 클립이 어느 쪽을 머리로 보는지 보정 |
| `m_alignPullSpeed` / `m_flightAlignPullSpeed` | 1.5 / 16 | 원격이 시체를 루트로 당겨오는 속도 (착지 후 / 비행 중) |
| `m_alignSnapDistance` | 2.5 | 이만큼 벗어나면 스냅. **안전망이라 정상 동작에서는 안 걸려야 한다** |

### 텀블 — `RagdollRig`

`m_tumbleBias` (0.8) — 골반보다 높은 뼈에 얹는 추가 속도. 상체가 더 빨라 다리가 끌리는 회전이 생긴다.

## 5. 실측값 (2026-08-06)

탄도 공식을 그대로 믿어도 된다. 구르는 사지의 마찰이 사거리를 크게 먹을 것이라 의심했지만
**아니었다** — 착지 후 구르는 거리가 짧아진 공중 구간을 메운다.

```
체공 t = (vy + √(vy² + 2·9.81·0.9)) / 9.81      // 골반이 지면 0.9m에서 출발
수평 거리 ≈ vx · t · k
```

`k`는 세기에 따라 커진다(세게 칠수록 더 구른다): 약한 임펄스에서 **94%**, 지금 값에서 **105%**.

**사망 사거리는 3.3m다** (피해 150 · 가장자리 0.2 · 반경 8 · HP 100) — 임펄스가 실제로 쓰이는
구간은 폭심~3.3m뿐이고 그 밖은 살아서 넉백만 받는다. 튜닝은 이 좁은 띠만 보면 된다.

| 사망 위치 | 수평 거리 | 정점 |
|---|---|---|
| 폭심 | 약 12m | 3.2m |
| 3.3m (사망 경계) | 약 6m | 1.5m |

실측 검증 — 폭탄 1.45m에서 사망: 오너 **9.05m** / 원격 **9.10m** (이론 8.66m).

## 6. 셋업

리그는 **Unity 내장 Ragdoll Wizard**(`GameObject > 3D Object > Ragdoll…`)로 만들고,
그 위에 **`Tools > Player > Finish Ragdoll Setup`**을 돌린다.

위저드는 콜라이더와 `CharacterJoint`까지만 만든다. 셋업 스크립트가 하는 나머지:

1. `Ragdoll` 레이어 확보 (슬롯 10) + 충돌 매트릭스 — **지형(Default)하고만** 부딪힌다
2. `isKinematic = true` 초기화 (위저드는 켠 채로 둬서 그대로 두면 스폰 즉시 무너진다)
3. 보간·CCD, 관절 preprocessing 해제
4. **검증** — 전 뼈가 몸통 리그 아래인지 확인하고, 아니면 아무것도 고치지 않고 중단한다

⚠ **위저드에 뼈를 넣을 때 `Root/Hips` 이하만 지정할 것.** 플레이어 프리팹에는 뼈 이름이 완전히
같은 리그가 **두 벌** 있다(1인칭 팔이 리그 복사본이다). 잘못 집으면 사망 시 1인칭 팔이 물리로
풀려 바닥에 떨어진다. → `RagdollRig.m_boneRootName` 툴팁

**콜라이더 크기·관절 축·질량 분배는 위저드의 몫이라 스크립트가 건드리지 않는다.**
solver 반복·겹침 탈출 속도는 프리팹에 저장되지 않아 `RagdollRig`가 런타임에 건다. `§9-3`

현재 플레이어: **뼈 11개, 합계 70kg.**

## 7. 고장 났을 때 어디를 보나

| 증상 | 먼저 볼 곳 |
|---|---|
| 시체가 화면에서 사라진다 | 스킨 컬링 바운즈 — `SetSkinsAlwaysVisible` |
| 1인칭 팔이 바닥에 떨어진다 | 위저드에 FP 팔 뼈를 집었다 — 리그를 다시 만들 것 |
| 쓰러지는 순간 몸이 튄다 | 자기 캡슐과의 충돌 무시가 지워졌다 `§9-1` |
| 안 날아가고 제자리에 무너진다 | 래그돌이 취소됐는지 — 부활 오인 `§9-19` |
| 원격에서만 안 따라온다 | 오너의 캡슐 추종이 도는지. **원격은 오너의 거울이다** `§9-19` |
| 끌 때 시체가 날아간다 | 제자리 회전이면 공진 `§9-17`, 달리며 회전이면 슬링 `§9-18` |
| 시체가 허공에 굳는다 | 지면을 못 찾은 채 타임아웃 정착 `§9-9` `§9-14` |

## 8. NPC로 확장할 때

`RagdollRig`·`RagdollRope`는 그대로 쓸 수 있다. NPC 리그는 플레이어와 **같은 Synty 본 이름**
(`Root`/`Hips`/`Head`/`Spine_02`)을 쓰고, 리그가 한 벌뿐이라 FP 팔 함정도 없다.

새로 써야 하는 것은 `PlayerRagdoll`에 대응하는 오케스트레이션이다:

| | Player | NPC |
|---|---|---|
| 이동 프록시 | CharacterController (끄고 위치 대입) | **NavMeshAgent** (끄고, 정착 후 `Warp`) |
| 위치 권위 | **오너** 권한 NetworkTransform | **서버** 권한 → 전 클라가 원격 |
| 진입 트리거 | `PlayerIncapacitation.IsDead` | ? — 아래 참고 |

### 선행 과제 — 코드 구조가 아니다

1. **리그 빌드가 Player 전용이다.** `PlayerRagdollSetup.k_prefabPath`가
   `Assets/Prefabs/Player.prefab` 하드코딩이고, NPC 프리팹에는 `CharacterJoint`가 하나도 없다.
2. **NPC에 사망 개념이 없다.** HP 0이 `Stun`으로 간다 — "언제 래그돌에 들어가나"를 먼저 정해야 한다.
   (`BombDevice.ServerExplode`의 "NPC 폭발 피해는 아직 연결하지 않았다" 주석과 같은 매듭)

### 밧줄은 합치지 말 것

NPC에도 밧줄이 있지만(`NpcController.Rope`) **메커니즘이 다르다** — 그쪽은 서버가
`transform.position`을 직접 대입하고 NetworkTransform이 복제한다. 래그돌이 된 몸은 동적
리지드바디라 그 방식이 통하지 않아(부모 트랜스폼을 따르지 않는다) 관절 방식이 필요했다.
**갈리는 기준은 "대상이 래그돌이냐 아니냐"다.**

## 9. 남은 것

- **시체 무게가 운반자를 늦추지 않는다.** `RopeDragLoad`(#398)가 NPC 견인에만 붙어 있어, 70kg을
  끌면서도 스프린트로 원을 그릴 수 있다. 붙이면 슬링 캡(`m_maxSpeed`)에 걸릴 일 자체가 줄지만,
  무게는 ω를 줄일 뿐 상한을 보장하지 않으므로 **캡은 그대로 남겨야 한다.**
- **NPC 래그돌** — 위 §8.
