# 제보 전화 — 라운드 도중 수배 공개 설계 (#102)

> 상태: 설계 확정 — 구현 플랜 대기
> 선행 완료: #127(다수 진범 배정) · #58(수배 UI) · #331(진범 수 HUD, `TotalWanted`)

## 0. 목표

본부에 간헐적으로 오는 제보 전화를 받으면 **수배 리스트에 용의자가 1명 추가**된다. 전화 내용은 중요하지 않고 **받는 행위 자체가 기능**이다 — 이게 "본부에 최소 1명 상주"의 이유이자 "전화 오기 전까지만 현장 다녀오자"는 도박을 만든다 (GDD 4-2).

이슈 본문의 설계(예비 용의자 풀 — 전부 미리 확정, 공개만 나눈다)를 그대로 채택한다. 아래는 그 위에서 확정한 것과, 코드를 붙일 이음새다.

## 1. 확정 결정

1. **라운드 시작에 예비 풀 전체를 확정한다** — 최대 수배 수만큼 용의자를 뽑고 외형·디코이·몽타주까지 만들어 둔다. 전화 시점에 몽타주를 역생성하지 않는다(부합 인원 수를 통제할 수 없어 디코이 설계가 깨진다).
2. **`IsCriminal`이 곧 공개 플래그다** — 예비 용의자는 `IsCriminal = false`로 대기하고, 승격 시점에 켠다. 미공개 용의자를 잡으면 **오검거**로 판정된다(GDD 7-3 정의와 일치).
3. **승격은 `OnMontageGenerated`를 재사용한다** — 별도 등록 경로를 만들지 않는다. `WantedListManager`가 `NetworkList` 추가와 `TotalWanted` 증가를 이미 그 핸들러에서 하므로 추가 작업이 없다(#331 담당자 문의에 대한 답).
4. **수배 HUD 분모는 라운드 도중 늘어난다** (2026-07-27 확정) — 결정 3의 결과다. `0/1 → 전화 받음 → 1/2`처럼 올라간다. 공개된 수배만 분모에 잡히므로 "수배 리스트에 있는 놈만 잡아라"와 일관되고, 남은 분량을 미리 알 수 없다는 긴장이 유지된다.
5. **예비 풀이 소진되면 전화가 오지 않는다** (2026-07-27 확정) — 수신 타이머를 멈춘다. 받아도 아무 일 없는 전화는 플레이어를 속이는 셈이고, 본부 상주 압박도 그 시점엔 풀어주는 게 맞다.
6. **승격 시 검거 반응을 범인 가중치로 재추첨한다** — 예비 용의자는 시민 가중치(순응 80%)로 뽑혀 있다. `Reaction`은 서버 전용이라 바꿔도 플레이어에게 티가 나지 않는다.

### 튜닝값은 인스펙터로 뺀다

플레이테스트로 정할 값이라 코드를 막지 않는다. 기본값은 출발점일 뿐이다.

| 값 | 기본 | 의미 |
|---|---|---|
| 울림 지속시간 | 15초 | 이게 곧 "현장 다녀올 수 있는 시간"이라 체감에 직결된다 |
| 수신 간격 | 40~90초 | 불규칙 범위 |
| 최대 수배 수 | 3 | 예비 풀 크기. 할당량 이슈와 연동될 값 |
| 최초 공개 수 | 1 | 라운드 시작에 이미 공개된 수 |

## 2. 아키텍처 · 데이터 흐름

기존 파이프라인은 **건드리지 않는다.** 마지막 발행 지점만 공개분/대기분으로 가른다.

```
라운드 시작 (기존 그대로)
  OnSpawnCompleted → CriminalAssigner.AssignAll()
    ├─ 최대 수배 수만큼 용의자 선정
    ├─ 앞 N명(최초 공개 수)만 AssignProfile(profile, isCriminal: true)
    └─ 나머지는            AssignProfile(profile, isCriminal: false)   ← 대기
  → OnCriminalAssigned → AppearanceAssigner.AssignAll()
    ├─ PickRevealedAxes()  — 공개 축은 여기서 한 번만 뽑는다(라운드 내내 고정)
    ├─ 예비 풀 전원의 외형·디코이·몽타주 생성 (m_montageTexts에 순서대로 보관)
    └─ OnMontageGenerated 발행은 IsCriminal == true 인 대상만            ← 여기가 갈림

라운드 도중
  TipCallPhone: 서버 타이머 → m_isRinging = true (동기화)
    ├─ 플레이어 E → ServerRpc → CriminalAssigner.PromoteNext()
    │     ├─ 대기 목록에서 유효한 후보 1명 선택 (§3 가드)
    │     ├─ identity.SetCriminal(true) + 반응 재추첨
    │     └─ AppearanceAssigner.RevealMontage(npc)
    │           └─ 보관해 둔 몽타주로 OnMontageGenerated 발행
    │                 └─ WantedListManager: NetworkList 추가 + TotalWanted++ (기존 코드)
    └─ 울림 시간 초과 → 놓침. 승격 없이 다음 수신 예약
```

**공개 축이 라운드 내내 고정된다**는 점이 이 설계의 핵심 이점이다. `PickRevealedAxes()`를 중도에 다시 부르지 않으므로 본부에 떠 있던 기존 몽타주가 무효화되지 않는다.

### 신규 API

| 대상 | 추가 | 비고 |
|---|---|---|
| `CitizenIdentity` | `SetCriminal(bool)` | 서버 전용. `AssignProfile`에서 범인 여부만 떼어낸 진입점 |
| `CriminalAssigner` | `PromoteNext()` → `bool` | 승격 성공 여부 반환. 서버 전용 |
| `CriminalAssigner` | `HasPendingSuspect` | 전화가 계속 올지 판단하는 값 (결정 5) |
| `AppearanceAssigner` | `RevealMontage(NpcController)` | 보관해 둔 몽타주로 발행 |
| 신규 | `TipCallPhone` | 본부 배치 `IInteractable` + 서버 타이머 |

`AppearanceAssigner`는 `IsCriminal`을 읽지 않고 `CriminalAssigner.CriminalNpcs`만 보므로 **선정 로직은 그대로 둔다** — 발행 조건만 바뀐다.

## 3. 승격 가드 (필수)

승격 대상이 이미 무효해졌을 수 있다. 아래는 건너뛰고 다음 후보로 넘어간다. **가드가 없으면 아무도 못 잡는 유령 항목이 수배 리스트에 남는다.**

| 건너뛸 대상 | 왜 |
|---|---|
| 이미 판정된 NPC (`ArrestJudge.JudgedNpcs`) | 미공개 상태에서 오검거로 잡혀 사라진 경우. 그 몽타주를 등록하면 대상이 없다 |
| 디스폰된 NPC | 같은 이유 |
| 연행 중인 NPC (`PlayerEscorter`) | 곧 판정될 대상이라 등록 직후 사라진다 |

후보를 다 훑어도 유효한 대상이 없으면 승격 실패로 두고, 그 시점부터 풀 소진으로 본다(결정 5).

## 4. 제보 전화 오브젝트 (`TipCallPhone`)

- **서버 권위.** 수신 타이머·승격은 서버에서만 돌고, 울림 여부만 `NetworkVariable<bool>`로 동기화한다. 벨소리·표시는 각 클라의 로컬 연출이다.
- `IInteractable` — `CanInteract()`는 **울리는 중에만** true. 조준 윤곽선이 울릴 때만 켜진다.
- `Interact()`는 클라에서 불릴 수 있으므로 **서버에서 한 번 더 검증**한다(울리는 중이 아니면 무시). 클라 게이팅만으로는 RPC 직접 호출을 막지 못한다 — `CCTVSwitcher.RequestTogglePowerRpc`가 먹통 중 전원 조작을 서버에서 재차 막는 것과 같은 이유.
- 울림 시간이 지나면 스스로 끊고 다음 수신을 예약한다. 놓친 기회는 복구되지 않는다.

## 5. 이 이슈에서 코드로 끝나지 않는 것

**전화기를 씬에 배치하고 배선하는 작업은 Editor에서 해야 한다.** 컴포넌트와 상호작용 경로는 코드로 만들지만, 본부 어디에 두고 어떤 모델·콜라이더를 쓸지는 씬 작업이다. PR의 씬·프리팹 섹션에 반드시 기재한다.

벨소리(오디오)도 이 범위 밖이다 — 울림 상태는 동기화되므로 나중에 연출만 붙이면 된다.

## 6. 위험 · 미해결

- **최초 공개 수 0의 경우** — 라운드 시작에 수배가 아무도 없는 구성도 인스펙터로는 가능하다. 그때 HUD 분모가 0으로 시작하는데 표시가 깨지지 않는지 확인 필요.
- **`m_criminalCount`의 의미가 바뀐다** — 지금은 "이번 라운드 진범 수"인데 앞으로는 "예비 풀 크기(최대 수배 수)"다. 인스펙터 툴팁과 로그 문구를 함께 고쳐야 오해가 없다.
- **라운드 할당량과의 관계** — 예비 풀 크기가 곧 라운드 최대 수배 수라 할당량 이슈와 값이 맞물린다. 이 이슈에서는 인스펙터 값으로 두고, 할당량 쪽이 확정되면 그쪽이 주도한다.

## 7. 테스트

Main Scene, 단독 Play + **MPPM 2인**.

1. 라운드 시작 → 수배 리스트에 **1명만** 뜨는지. 예비 풀은 확정됐지만 안 보여야 한다.
2. **미공개 용의자를 검거·인계 → 오검거 판정**(보상 없음). 유령 항목이 생기지 않는지.
3. 전화 수신 → 받기 → **수배 리스트에 1명 추가**되고 HUD 분모가 1 늘어나는지.
4. 추가된 용의자를 검거·인계 → **진범(유효 검거)** 판정.
5. **공개 축이 안 바뀌었는지** — 3번 이후에도 기존 몽타주로 1번 용의자를 계속 찾을 수 있어야 한다.
6. **전화를 안 받고 방치** → 울림이 끊기고 수배가 그대로인지. 다음 전화는 오는지.
7. **미공개 용의자를 오검거로 없앤 뒤 전화 받기** → 그 대상을 건너뛰고 다음 후보가 승격되는지(§3 가드).
8. **풀 소진 후** → 전화가 더 이상 오지 않는지(결정 5).
9. **MPPM** — 울림 표시가 양쪽에 보이고, 한쪽이 받으면 양쪽에서 수배 리스트가 같이 갱신되는지.
10. 울리지 않을 때 E → 아무 반응 없고 윤곽선도 없는지.
