# #725 완전 사망 전 유예 시간 — 구현 계획

## Context

지금은 HP가 0이 되는 순간 곧바로 `IncapacitationCause.Die`(기능 정지)가 되고, 그 뒤로는 동료가 **부활 키트**(#613)를 들고 와야만 일어난다. 키트가 없거나 아무도 못 오면 한 번의 실수가 라운드 전체를 날린다.

HP 0 → **유예 구간 60초**(동료가 키트 없이 맨손으로 일으킬 수 있음) → **완전 사망**(키트 전용)으로 되돌린다. #524가 접었던 `Down` 상태를 다시 켜는 것이다. #524는 코드를 지운 게 아니라 **진입만 끊어놨고**(enum 값·`PlayerReviver`·HUD 분기 전부 보존) 되살리는 방법까지 주석으로 남겨 뒀다. 다만 #524가 접은 이유 — *구조·전멸 판정·HUD·운반이 두 갈래로 분기되는 비용* — 은 그대로이므로 그 분기를 이번에 전부 다시 배선한다.

핵심은 상태 하나를 늘리는 것이 아니라 **구조가 기억에 남는 장면이 되게 하는 것**이다. 그래서 조작은 창이 아니라 월드에서 몸으로 하고, 진행은 구조하는 쪽과 쓰러진 쪽 **양쪽에게** 보인다.

- 운반(#365)·본부 부활 장치·키트 좌클릭은 **완전 사망 전용 그대로** 둔다.

### 화면 밝기 = 유예 잔여, 하나만

쓰러진 본인 화면만 어두워진다. **밝기는 오직 유예 잔여 시간을 뜻한다** — 구조 진행률을 여기에 섞지 않는다. 섞으면 화면이 거짓말을 한다: 50초가 지나 거의 캄캄한데 구조로 밝아졌다가 중단되면 도로 캄캄해지는데, 그 사이 유예는 더 줄어 있어 "돌아왔다"가 사실이 아니게 된다.

대신 **구조 중에는 유예 시계 자체가 멈춘다.** 그러면 밝기가 정지하는 것이 곧 시계가 정지한 것이라 화면과 규칙이 어긋날 수 없다.

- 유예가 흐를수록 어두워진다 → 남은 시간을 숫자 없이 체감한다.
- 동료가 손을 대면 **그 밝기에서 멈춘다** → 셧다운이 붙들렸다는 것을 화면으로 안다.
- 손을 떼면 그 지점부터 다시 어두워진다 → 실패했다는 것도 화면으로 안다.
- 구조 완료 시 확 밝아진다. 완전 사망 시 완전 암전 → 관전 카메라로 열린다.
- 구조가 어디까지 갔는지(진행률)는 밝기가 아니라 **별도의 재부팅 표시**(진행 링 + "재부팅 중" 문구)가 맡는다.

시계를 멈추는 쪽을 택한 근거는 악용 여지가 없다는 것이다 — 붙어 있으면 어차피 3초 뒤 구조가 끝나므로, 붙었다 떼기를 반복해 시간만 끄는 것은 이득이 없다. 오히려 교전 중 "일단 붙어서 시간을 벌어 준다"는 협동 장면이 생긴다.

쓰러진 쪽이 재부팅 표시를 그리려면 **구조 중이라는 사실과 진행률**을 알아야 한다. 기존 채널링 게이지 통지(`NotifyChannelGaugeStart`)는 오너(구조자)에게만 가므로, `PlayerIncapacitation`에 동기화 값을 하나 더 둔다(아래 1번). 전 피어가 읽으므로 제3자 표현으로도 확장할 수 있다.

### 1. `Assets/Scripts/Player/Combat/PlayerIncapacitation.cs` — 유예 상태·타이머·구조 진행

#524 커밋 `c5952c5f`가 지운 코드를 되돌린다. `git show c5952c5f -- Assets/Scripts/Player/Combat/PlayerIncapacitation.cs` 의 `-` 라인이 거의 그대로 원본이다.

- `Down` enum 주석을 "휴면"에서 현역으로 되돌린다(`:15-19`). **값 순서는 절대 건드리지 않는다** — NetworkVariable 동기화 enum이라 순서가 곧 와이어 포맷(`:25`).
- `[SerializeField] private float m_dieAfterDownSeconds = 60f;`
- 유예 마감 동기화 `m_downDeadlineSynced`(`NetworkVariable<double>`) + `m_downDeadline` — **이미 있는 `m_stunDeadlineSynced`(`:67-68`)와 `SetStunDeadline`(`:352-357`)을 그대로 복제**한다. 시간 기준 `CurrentTime`(`:74-75`)도 이미 있다(#477이 되살려 둠).
- `RemainingUntilDie` — `RemainingStunSeconds`(`:105-115`)를 본뜬다. **화면 어두워짐과 HUD가 같은 값을 읽는다.**
- **신규** `m_reviveEndSynced`(`NetworkVariable<double>`) + `RemainingReviveSeconds` / `IsBeingRevived` — 구조 채널링이 언제 끝나는지. 같은 deadline 패턴이라 늦게 접속해도 즉시 맞는다. 쓰러진 본인의 재부팅 진행 표시가 이 값을 읽는다.
- **신규** `ServerSetBeingRevived(bool)` — `PlayerReviver`가 채널링 시작/종료 시 부른다. 여기서 **유예 시계를 멈추고 되돌린다**:
  - 시작: 그 순간의 `RemainingUntilDie`를 `m_downFrozenRemaining`(`NetworkVariable<float>`)에 박고 마감을 "정지" 표시로 둔다. 회차 토큰을 올려 돌던 `ServerDieTimerAsync`를 무효화한다.
  - 종료(완료·취소 무관): `마감 = CurrentTime + 얼어붙은 잔여` 로 되살리고 남은 초로 타이머를 새 회차로 다시 건다.
  - `RemainingUntilDie`는 정지 중이면 얼어붙은 값을, 아니면 `마감 − CurrentTime`을 돌려준다. **매 프레임 NetworkVariable을 쓰지 않는다** — 시도 1회당 쓰기 두 번뿐이라 트래픽이 늘지 않는다.
- `m_causeEpisode` 회차 토큰 + `ServerDieTimerAsync(int episode)` — `ServerStunTimerAsync`(`:290-309`)와 같은 골격. 회차가 어긋나면 무동작으로 끝나므로 일으켜진 뒤 다시 쓰러져도 옛 타이머가 완전 사망을 만들지 않는다.
- `SetCause`(`:312`): 원인이 바뀔 때마다 `m_causeEpisode++`, `Down`이면 마감 설정 + 타이머 시작, 아니면 마감 0. 구조 진행값도 함께 0으로.
- **덮어쓰기 가드를 `Die` 단독에서 `Die || Down`으로 확장**(`:230`). 근거는 기존 Die 가드와 같다 — 오검거 매달기 폴백(`WrongfulArrestPenalty.HangAsync`)이 무력화 여부를 보지 않고 `Penalty`를 걸면 30초 뒤 `Recover()`가 유예까지 함께 풀어 공짜 부활이 된다. `Down → Die` 전환은 `SetCause`를 직접 부르므로 이 가드를 타지 않는다.
- **신규** `ServerFinishOff()` — 유예 중인 몸을 즉시 완전 사망으로. `ServerKillByAbduction()`(`:269`)과 같은 모양.
- `IsOutOfAction`(`:95`)은 **손대지 않는다** — 전멸 판정도 조준 히트박스도 유예를 포함하는 것이 이번 결정이다.

### 4. 입력 재배치 — E는 일으키기, R은 뒤지기

`Assets/InputSystem_Actions.inputactions` 에 **`Loot` 액션 신설** (`<Keyboard>/r`). R·F·Q·C 모두 미사용이라 충돌이 없고, 왼손 기준 E보다 한 칸 멀어 **배신 행동이 손을 조금 뻗어야 닿는다** — 실수로 동료를 터는 사고가 줄고 의도와도 맞는다. `PlayerInputHandler`에 이벤트 + `LootBinding`(표시용 키 문자열) 추가 — 기존 `InteractBinding`/`UseItemBinding` 관례 그대로.

**일으키기 (E, 탭 후 유지)** — `Assets/Scripts/Player/Combat/PlayerReviver.cs`
- 현행 홀드 구독(`OnInteractStarted`/`OnInteractCanceled`, `:56-60`·`:65-69`)을 **탭 시작**으로 바꾼다.

**뒤지기 (R)** — `Assets/Scripts/Player/Loot/LootableBodyInteractable.cs` · `PlayerLooter.cs`

### 6. 연출 — 쓰러진 쪽 화면, 구조하는 쪽 모션

**쓰러진 쪽 (오너 전용, 신규)**
- 화면 어두워짐 표현을 새로 만든다. 위치는 `Assets/Scripts/Player/View/` — 피격 비네트(`PlayerHitView`, #476)와 같은 층이고, 그쪽의 오버레이 구성을 참고한다.
- 어둡기 = `1 - RemainingUntilDie / m_dieAfterDownSeconds`. **이 한 식이 전부다** — 구조 중에는 `RemainingUntilDie`가 얼어붙으므로 화면도 저절로 멈춘다. 밝기 쪽에 구조 관련 분기를 두지 않는 것이 핵심이다.
- 구조 진행은 별도 표시 — `IsBeingRevived`일 때 진행 링(`RemainingReviveSeconds` 기반) + "재부팅 중" 문구.
- 완전 사망 시 완전 암전 후 관전 카메라(`PlayerLook.cs:346`)로 넘어간다.
- HUD 문구는 `PlayerReviveHud`가 담당(7번).

**구조하는 쪽**
- 화면은 건드리지 않는다.
- 진행 게이지는 기존 `App.UI.Gauge`(`ChannelingGaugeUI`)를 그대로 쓴다 — `PlayerReviver.ServerChannelAsync`(`:196-214`)에 이미 배선돼 있다.
- 무릎 꿇는 모션: Animator에 쓸 클립이 있는지 먼저 확인하고, 없으면 **앉기(Crouch) 자세를 빌린다**. 전용 연출 없이 기존 클립을 빌려 쓰는 것은 이 프로젝트의 선례다(GDD 7-5 매달기·기절이 Knockdown을 빌린다).
- 루프음은 `ChanneledInteractionBehaviour.ChannelLoopSound` virtual을 override한다 — 게이지 숨김과 같은 경로라 "취소했는데 소리가 계속 난다"가 구조적으로 생기지 않는다.

**제3자** — 구조자의 무릎 꿇은 모션이 그대로 보인다. 별도 작업 없음.

### 7. HUD · 로컬라이제이션

- `Assets/Scripts/Player/View/PlayerReviveHud.cs`
  - `IsDowned` 분기(`:85`)가 다시 살아난다. `m_downedPrompt`에 **남은 초 인자를 복원**한다 — `:139-143` 주석에 제거 이력과 복원 방법이 그대로 적혀 있다.
  - 구조 중일 때(`IsBeingRevived`) 문구를 "재부팅 중"으로 바꾼다 — 화면이 밝아지는 것과 같은 신호를 글자로도 준다.
  - 조준 안내 문구: 홀드 안내인 `Hud.Revive.Hint`("[{0}]키를 홀드하여 구조")는 더 이상 맞지 않는다. 탭 방식 문구로 교체.
- 로컬라이제이션 — `Hud.Revive.Downed`에 `{0}` 복원, 신규 키(구조 중 문구·F 뒤지기 안내) 추가. **`HudTable Shared Data` / `HudTable_ko-KR` / `HudTable_en` 세 파일에 같은 `m_Id`로** 넣는다.
- ⚠ 두 함정: `LocalizedString.Arguments`는 반드시 `StringChanged` **구독 전에** 넣는다(`RemainingCriminalsHud.cs:101-102`). `LocalizedString`을 다른 `LocalizedString`의 인자로 직접 넣지 말고 `GetLocalizedString()`으로 미리 푼다(`InteractPromptView.cs:99-101`).

이슈 완료 기준 **"남은 유예 시간이 본인과 동료에게 보인다"** 는 본인=화면 밝기 + HUD 문구, 동료=조준 안내로 충족된다.

## 검증

1. **컴파일** — 저장 후 Unity Console에 에러가 없는지 확인(포커스 시 재컴파일). MCP 연결 시 `read_console` + `editor_state.isCompiling` 폴링.
2. **Multiplayer Play Mode 2인**(호스트 + 원격 클라) — 양쪽 시점에서 각각 본다:
   - 진압봉 3대 → 유예 진입. 자세는 **래그돌**(물리로 무너진다 — #865로 뒤집혔다), 시야 회전 가능, **화면이 서서히 어두워진다**
   - 동료가 겨냥 → `[E] 일으키기` / `[R] 뒤지기` 두 줄이 뜬다
   - E 한 번 → 무릎 꿇고 게이지가 찬다. **쓰러진 쪽은 화면이 그 밝기에서 멈추고 재부팅 표시가 뜬다.** 완료 시 부활(HP 부분 회복)
   - 구조 도중 이동/다른 입력 → 취소. **쓰러진 쪽 화면이 멈춘 지점부터 다시 어두워진다** — 밝아졌다 되돌아가는 것이 아니다
   - 구조를 붙였다 뗐다 반복해도 **유예가 늘지 않는다**(멈출 뿐 되감기지 않는다). 원격 클라에서도 남은 초가 서버와 어긋나지 않는지 함께 본다
   - 60초 방치 → 완전 암전 → 래그돌 + 관전 카메라
   - R → 약탈 창. 유예 중에도 소지품·자금이 넘어오고 털린 본인에게 알림이 뜬다
   - 유예 중 진압봉 추가 타격 → **즉시** 완전 사망(화면 즉시 암전)
   - 완전 사망한 몸에 좌클릭 + 부활 키트 → 현행대로 부활
   - 유예 중 밧줄 좌클릭(운반) 거부, 본부 장치·키트도 유예 대상 거부
   - 전원 유예 → 게임오버(전멸)가 즉시 뜬다
3. **원격 클라의 남은 시간·화면 밝기가 서버와 일치**하는지 — 서버 시각 기준이라 늦게 들어온 피어도 즉시 맞아야 한다.
4. **회귀** — 테이저 기절 5초 자력 기상, 오검거 매달기 30초, 납치 호송/린치, 그리고 **R로 옮긴 약탈(#487)이 완전 사망 대상에서 종전대로** 동작하는지.

## 열린 항목 / 위험

- **배신 루프가 강해진다.** 유예 중 약탈 + 유예 중 진압봉 확인사살이 합쳐지면 "눕히고 → 끝내고 → 턴다"가 성립한다. GDD 7-5의 ⚠ 팀 합의 항목(동료를 눕히는 것 자체에 페널티가 없다)이 실제로 커지므로 문서에 갱신해 남긴다.
- **마지막 한 명에게는 유예가 없다** — 전멸 판정 포함 결정의 귀결. 플레이테스트에서 다시 볼 지점.
- **약탈 키 이동(E→R)은 #487의 확정 조작을 바꾸는 것**이다. 팀에 공유가 필요하고, GDD와 조작 안내를 함께 고쳐야 한다.
- **무릎 꿇는 모션 클립이 없을 수 있다** — 앉기 자세를 빌리면 "구조하는 느낌"이 기대만큼 안 나올 수 있다. 클립 확인이 이 이슈에서 연출 품질을 가르는 지점이다.
