# 진압봉 타격 — 그립·스윙 애니메이션·타이밍 (#217)

> 진압봉(Baton) 아이템의 손 그립과, **1인칭 팔 / 3인칭 몸 / 데미지 판정** 세 가지를 한 순간에 맞추는 구조를 다룬다.
> 게임 규칙(데미지·기절)의 정본은 [GDD.md](GDD.md) 7-4, 코드 구조 규칙은 [architecture.md](architecture.md).

## 1. 한눈에

좌클릭 한 번에 세 가지가 각각 일어난다. 리그도 재생 방식도 전부 달라서, **같은 상수를 보게 묶어 두지 않으면 조용히 어긋난다.**

| 보는 사람 | 무엇이 재생되나 | 어떻게 |
|---|---|---|
| 나 (오너) | 카메라 하위 FP 팔 | `PlayerHandView`의 **절차적 스윙** (코드로 팔을 흔든다) |
| 남 (다른 피어) | 캐릭터 모델 상체 | `Player.controller`의 **UpperBodyAttack 레이어 클립** |
| 서버 | 데미지 판정 | `Baton`이 임팩트 시점까지 대기 후 스피어캐스트 |

```
t = 0.00s   좌클릭 → 서버 검증 → 전 피어에 스윙 재생 (판정 없음)
t = 0.30s   ★ 임팩트 — 1인칭·3인칭·데미지가 모두 이 순간
t = 0.64s   스윙 종료, 기본 자세 복귀
t = 0.90s   쿨다운 해제 (다음 타격 가능)
```

## 2. ⚠️ Animator 창에서 Speed를 직접 고치지 말 것

`Attack_Baton` 상태의 **Speed(1.40)** 와 복귀 전환의 **Exit Time(0.64)** 은 손으로 만지면 안 된다. 두 가지 이유가 있다.

**1. 빌더가 덮어쓴다.** `Player.controller`는 손으로 유지하는 에셋이 아니라 [PlayerAnimatorControllerBuilder](../Assets/Scripts/Editor/PlayerAnimatorControllerBuilder.cs)가 생성하는 산출물이다. `Tools > Player > Create Animator Controller`를 누구든 한 번 돌리면 손 편집은 사라진다.

**2. 싱크가 깨진다.** 3인칭 임팩트 시점은 `0.42초 ÷ Speed`다. Speed만 1.8로 올리면 3인칭은 0.23초에 때리는데 1인칭과 데미지는 0.30초 그대로라, **내 화면에선 아직 휘두르는 중인데 남의 화면에선 이미 맞은** 상태가 된다. 정확히 이 버그를 한 번 겪고 고친 구조다.

### 타이밍을 바꾸려면

[PlayerAnimationDriver](../Assets/Scripts/Player/PlayerAnimationDriver.cs)의 두 상수만 고친다. 셋 다 여기서 파생된다.

```csharp
public const float k_swingImpactSeconds = 0.3f;   // 맞는 순간
public const float k_swingSeconds = 0.64f;        // 전체 길이
```

고친 뒤 **`Tools > Player > Create Animator Controller`를 반드시 한 번 실행**해야 컨트롤러 에셋에 반영된다 (1인칭과 데미지는 재컴파일만으로 따라오지만 3인칭은 에셋이라 그렇지 않다).

지킬 것:
- `k_swingSeconds` < `Baton.m_cooldownSeconds`(0.9초). 넘기면 다음 타격이 이전 스윙을 잘라먹는다.
- `k_swingImpactSeconds`를 너무 줄이면 3인칭 배속이 과해져 동작이 뭉갠다. 현재 1.40배.

Animator 창은 **결과 확인용**으로만 쓴다: `Assets/Animation/Player`(폴더가 아니라 `Player.controller`다 — 블렌드 트리가 하위 에셋으로 딸려 폴더처럼 펼쳐진다) 더블클릭 → 좌상단 `Layers` 탭 → `UpperBodyAttack` → `Attack_Baton` 노드.

## 3. 왜 1인칭만 절차적인가

FP 팔(`Player/Camera/FPArm_Right`)은 [FPArmGenerator](../Assets/Scripts/Editor/FPArmGenerator.cs)가 캐릭터 모델의 오른팔 메시만 떼어내 만든 **애니메이터도 아바타도 없는 정적 스킨드 메시**다. 3인칭 상체 클립이 여기엔 도달하지 않는다.

애니메이터를 새로 붙이는 대신 팔 루트를 코드로 흔든다. 팔 루트의 원점이 곧 어깨라(생성기가 `skeletonTop`을 shoulder 위치만큼 당겨 놓는다) 이 회전은 **어깨를 축으로 팔 전체가 도는** 그림이 되고, 손 본에 붙은 아이템도 함께 휘둘린다. 기존 bob/sway(#265) 위에 얹히므로 걷거나 점프하면서 휘둘러도 두 움직임이 함께 산다.

### 포즈 값을 조정할 때

`PlayerHandView`의 `s_swing*Euler` / `s_swing*Offset`. 회전은 팔 로컬이 아니라 **카메라(부모) 축** 기준이다 (X=위아래, Y=좌우, Z=롤).

두 가지가 이 값들을 제약한다.

**프레임 이탈** — 팔이 기본 자세부터 이미 화면 오른쪽 아래(뷰포트 약 0.80, 0.21)에 있고 회전축이 어깨라, 각도를 조금만 키워도 손이 화면 밖으로 나간다. 실제로 팔로스루에서 손이 y=-0.02까지 내려가 **봉만 떠 있고 주먹이 없는** 프레임이 나왔던 적이 있다. 현재 값의 실측 여유는 아래와 같다.

```
손 최저 y = 0.044   손 최대 x = 0.942   (0 또는 1을 넘으면 이탈)
```

**롤이 싸다** — 롤은 손 위치를 거의 안 건드리면서 봉만 돌린다 (계측: 롤 26→40으로 14도를 더 줘도 손은 0.06→0.04, 봉 기울기는 -41°→-49°). 그래서 역동성은 롤에서 벌고, 손을 옮기는 X·Y는 아낀다. 팔로스루도 아래(X)가 아니라 옆(Y)+롤로 흘린다.

### 가속 곡선

구간마다 곡선이 다른 것이 역동성의 핵심이다. 전부 `SmoothStep`으로 깔면 내려치기가 **임팩트 직전에 감속**해서 — 가장 빨라야 할 순간에 브레이크를 밟는 셈이라 — 휘두르는 게 아니라 훑는 것처럼 보인다.

| 구간 | 곡선 | 이유 |
|---|---|---|
| 준비 | 감속 `EaseOut` | 빠르게 젖혔다 잠깐 멎어 다음 동작을 예고 |
| 내려침 | **가속 `EaseIn`** | 임팩트 순간이 최고 속도 |
| 팔로스루 | 감속 `EaseOut` | 힘이 풀리며 흘러나감 |
| 회수 | `SmoothStep` | 조용히 복귀 |

경계는 전부 속도가 이어진다. 준비→내려침과 팔로스루→회수는 양쪽 다 0에서 만나고, **임팩트는 반대로 양쪽 다 최고 속도로** 만난다 — 여기서 0이 되면 봉이 맞는 순간 허공에 멈춰 선다.

## 4. 3인칭 클립

`HumanM@Attack1H01_R` (1.40초). 클립 경로는 빌더의 `k_attackClip`.

**반드시 `_R`(오른손) 클립일 것.** 아이템은 오른손 본(`Hand_R/HeldItemAnchor`)에 붙으므로 `_L`을 쓰면 왼손으로 휘두르는데 봉은 오른손에 붙어 따로 논다. 에셋에 좌우가 모두 있으므로 미러링은 필요 없다.

같은 `_R` 중에서도 **01**을 쓰는 이유가 두 가지다 (02·03은 왼쪽→오른쪽 백핸드):

1. 1인칭 스윙이 오른쪽→왼쪽 정타라, 백핸드를 쓰면 내가 보는 팔과 남이 보는 내 몸이 서로 반대로 휘두른다.
2. 임팩트에 봉 끝이 화면 정면 한가운데(좌우 +0.24m, 앞 1.90m, 카메라에서 1.95m)를 지난다. 타격 판정이 카메라 정면 스피어캐스트(사거리 2m)라 보이는 궤적과 판정선이 맞는다. 02는 같은 순간 봉이 오른쪽으로 1.07m 치우쳐 어긋났다.

### 클립을 교체하면

빌더의 **`k_attackClipImpactNormalized`(현재 0.30)를 반드시 다시 재서 갱신할 것.** 이 값이 틀리면 배속 계산이 틀어져 싱크가 깨진다. 재는 법은 클립을 리그에 `SampleAnimation`하며 봉 끝의 전방 도달이 최대가 되는 정규화 시점을 찾으면 된다.

`exitTime`과 배속은 상수로 박혀 있지 않고 `k_swingSeconds` / `k_swingImpactSeconds`에서 계산되므로, 클립을 갈아끼워도 위 값만 맞으면 싱크는 저절로 맞는다.

### 상체 레이어

Base Layer가 아니라 **레이어 1(UpperBodyAttack)** 에 마스크로 얹는다. 하체는 Base Layer의 이동·점프·앉기가 그대로 돌아, 점프하면서 공격 / 앉아서 공격이 별도 상태 없이 성립한다. Base Layer 상태로 넣었다면 (지상/공중/앉기) × (타격중/아님) 조합마다 전환을 깔아야 했다.

마스크(`UpperBodyAttack.mask`)는 Body(척추)를 켜는 게 핵심이다 — 스윙은 척추 회전이 동작의 대부분이라 팔만 켜면 팔을 휘적거리는 그림이 된다. Root는 반드시 끈다(켜면 공중에서 자세가 튄다). NPC의 `UpperBodyCuffed`와 Body 하나만 다른데, 그쪽은 '포즈'라 척추를 로코모션에 맡기는 게 맞아 마스크를 공유하지 않는다.

## 5. 데미지가 임팩트에 들어가는 이유

좌클릭 순간에 데미지를 넣으면 봉이 아직 뒤로 젖혀져 있는데 NPC가 먼저 맞는다. 그래서 애니메이션만 먼저 전 피어에 재생시키고, `k_swingImpactSeconds`만큼 기다렸다가 캐스트한다 (`Baton.ServerResolveHitAtImpactAsync`).

대기 골격은 [ServerChannel](../Assets/Scripts/Interaction/ServerChannel.cs)(#109)을 재사용한다. 홀드 채널링은 아니지만 필요한 게 같다 — 서버 전용 타이머, CTS 소유, 재진입 가드, 디스폰 시 정리.

**조준은 소지자 로컬 좌표로 환산해 들고 간다.** 월드로 굳혀 두면 대기하는 0.3초 동안 플레이어가 걷거나 도는 순간 조준선이 몸에서 떨어져 나가, 화면에선 정면을 후려치는데 판정은 0.3초 전 허공에서 나간다. 방향도 몸 기준이라 스윙 도중 마우스로 다시 겨누는 것은 여전히 안 된다.

취소되는 경우:

| 상황 | 취소되나 |
|---|---|
| 좌클릭을 뗌 (`CancelUse`) | **아니오** — 시작된 스윙은 끝까지 간다 |
| 아이템을 버림 (`ServerCancelActiveUse`) | 예 |
| 디스폰 / 파괴 | 예 |
| 스윙 도중 소유권이 남에게 넘어감 | 예 (판정 직전 재확인) |

## 6. 손 그립

`HandGrip.Handle` — 자루형 전용 프리셋. `Trigger`(검지 폄)와 달리 검지까지 다섯 손가락을 같은 깊이(72°)로 말고, 엄지는 바깥으로 벌리지 않고 자루 위를 덮는다(Z 음수). 적용은 `PlayerHandView.CurlEuler`.

> `HandGrip` enum 값은 프리팹에 int로 직렬화된다. **추가는 반드시 끝에** — 중간에 끼우면 기존 아이템의 그립이 밀린다.

### Baton 프리팹 그립 값

```
m_handGrip           = Handle
m_heldPositionOffset = (0.09, 0.02, -0.022)
m_heldRotationOffset = (90, 135, 0)
```

Synty 진압봉(`SM_Wep_Baton_01`)은 톤파형이다 — 주 봉이 로컬 +Y로 0.85m, 보조 손잡이가 +Z로 0.2m. 정점을 Y축으로 슬라이스해 보면 구조가 드러난다.

```
y[-0.15..-0.10] 반경 0.039   폼멜
y[-0.10.. 0.05] 반경 0.028   손잡이   ← 주먹이 잡는 곳 (중심 y=-0.025)
y[ 0.05.. 0.10] 반경 0.039   가드
y[ 0.10.. 0.20] z→0.206      보조 손잡이
y[ 0.65.. 0.70]              긴 봉 끝
```

손 본(`Hand_R`) 기준으로 축은 **+X = 손가락 방향, ±Z = 너클 축, +Y = 손바닥 쪽**이다. 위 값은 손잡이 축이 너클 축을 타고 주먹 중심에서 9mm 안(봉 반경 28mm)을 지나가고, 봉은 엄지·검지 쪽으로, 보조 손잡이는 손등 위(너클 가드)로 나가게 맞춘 것이다. 회전 Y=135°는 정면에서 봉이 화면 밖으로 나가지 않도록 45° 앞으로 눕힌 값이다.

이 오프셋은 1인칭·3인칭이 **공유한다** — 한쪽만 맞추는 방법은 없다.

## 7. 건드릴 때 함께 봐야 하는 것

| 바꾸는 것 | 함께 확인 |
|---|---|
| `k_swingImpactSeconds` / `k_swingSeconds` | 빌더 재실행 필수. 쿨다운(0.9초)보다 짧은지 |
| `Baton.m_cooldownSeconds` | `k_swingSeconds`보다 긴지 |
| `k_attackClip` (3인칭 클립) | `k_attackClipImpactNormalized` 재계측. `_R` 클립인지 |
| `s_swing*Euler` (1인칭 포즈) | 손이 뷰포트 [0,1] 안에 남는지 |
| `HandGrip` enum | 값 추가는 끝에만 |
| `m_held*Offset` | 1인칭·3인칭 양쪽에 적용된다 |

## 8. 미검증

정적 검증(클립 샘플링, 뷰포트 계측, 에디터 렌더링)까지만 했다. **플레이 모드·MPPM 실제 구동은 돌리지 않았다.** 남은 확인 사항:

- 0.3초 지연 동안 NPC가 걸어 나가면 빗나간다 — 의도한 동작이지만 체감상 답답한지
- 3인칭 1.40배속이 어색하지 않은지
- 원격 클라이언트에 핑이 있을 때 세 타이밍이 여전히 맞는지
- 스윙 도중 아이템을 버렸을 때 타격이 실제로 취소되는지
