## 3. 확정된 것

1. **A-1(사망 중 소유권 서버 이관)은 동작한다.**
   `[소유권] 시체#9 원인=사망 오너 2→0 플레이어오브젝트유지=True` — 계획서 §4 함정 2(플레이어
   오브젝트 연결 유지)의 답이 **True**다.
2. **A-2로 잡은 부작용 셋** (`2eb32cbf`) — `IsOwner`를 "내 캐릭터인가"로 쓰던 자리가 이관으로 뒤집힌 것:
   캡슐 추종 주체 · 이름표(placeholder `Name` 노출 + 빌보딩 정지) · HP·피격 연출.
3. **밧줄 견인은 살아났다** — `[밧줄추적] … 관절=걸림 끌림=예`.
   ⚠ 단 `[운반] 종료(대상을 놓침 — 너무 멀어짐)`은 **여전히 뜬다**(그 세션에서 5회, NPC 시체 2회).
4. **낙하는 자유낙하의 6~7배 느리다.** 골반 0.66m에 약 2.5초(자유낙하 0.36초).
   구간 속도가 **0.16~0.72m/s**로 계단을 그린다(움직였다 멈췄다).
5. **견인 중 뼈는 빠른데 몸이 안 나간다** — `평균속도`(뼈 평균 선속도) **7.0~8.6m/s**인데 골반은
   0.2~1.1m/s. `RagdollRope.ClampSpeed(m_maxSpeed = 8)` 상한에 계속 붙어 있다.

## 4. 다음 한 걸음 — 겹침 탈출 속도 실험 (에디터, 리빌드 불필요)

`[리그물리]`가 매 사망에 이렇게 찍는다:

```
[리그물리] 시체#9 오너0 나0 뼈=17 골반질량=10.9kg 선형감쇠=0.00 각감쇠=0.05
           중력=True 침투해소상한=0.50m/s 솔버=12/4 중력크기=9.81m/s²
```

`침투해소상한 = 0.5m/s`는 **엔진·프로젝트 기본값(10)의 1/20**이다. 겹친 콜라이더를 밀어내는 속도가
그 값으로 묶이므로, 접촉이 이어지는 동안 몸은 초당 0.5m로만 빠져나온다 — §3-4의 구간 속도
(0.16~0.72m/s)가 정확히 그 스케일이다.

**이 값은 이제 인스펙터 필드다** — `RagdollRig`의 `Max Depenetration Velocity`
(기본값 0.5, 즉 켜도 동작 변화 없음. 커밋 안 된 로컬 변경, §6).

### 절차

1. `Player` 프리팹 → `Ragdoll Rig` → `Max Depenetration Velocity`를 **10**으로
2. 죽어서 `[낙하속도]`의 `낙하곡선`·`최고하강`을 본다

| 결과 | 결론 | 다음 |
|---|---|---|
| 곡선이 앞당겨진다(`0.25s`에 0.3m 이상) | **확정** — 접촉 해소가 낙하를 지배했다 | 튀어오름과의 절충값 찾기(2~4). 값의 원래 목적은 "시체가 튀어오르는 높이"를 1.3cm로 묶는 것이었다(그 상수 주석) |
| 곡선이 그대로다 | 접촉 해소가 아니다 | **관절 쪽**을 본다 — 사망 순간 자세와 관절의 `connectedAnchor`(바인드 기준으로 구워짐, `autoConfigureConnectedAnchor = 1`)가 어긋나 솔버가 낙하 대신 관절 오차를 푸는 그림. `RestoreBindPose` 주석의 "1차 0.0055m → 2차 0.0624m 누적"이 같은 계열의 기록이다 |

⚠ `RagdollRig`는 **NPC도 함께 쓴다** — 값을 올리면 NPC 시체도 같이 바뀐다. 그것이 "NPC까지
느려진다"는 관측과 앞뒤가 맞는 점이기도 하다.

## 5. 계측 사용법 (전부 임시 — 원인이 잡히면 지운다)

플래그는 `Player.prefab` · `NPC_Citizen.prefab`에 **켜 둔 상태**다.

| 태그 | 어디서 | 무엇을 |
|---|---|---|
| `[리그물리]` | 사망 1회 | 질량·감쇠·중력·**침투해소상한**·솔버 |
| `[낙하속도]` | 사망 후 3초 창 | `비율`(물리÷실시간) · `최장프레임` · **`낙하곡선`**(0.25/0.5/1/2/3초 누적) · `최고하강` |
| `[밧줄]` / `[밧줄추적]` | 견인 시작 / 1.5초 뒤 | `관절`·`끌림`·`골반바디` · **`견인곡선`**(0.5/1/1.5초) · `최고속도` · 골반 키네마틱·잠듦 |
| `[자세도착]` | **원격 전용**, 2초 창 | 패킷/유실/`평균간격`/**`재생배율`**/`홀드` |
| `[래그돌대역폭]` | 권위, 2초 창 | 패킷·Hz·페이로드B·초당KB·원격수·업링크. + `[래그돌대역폭 합계]` 전 시체 합산 |
| `[운반경로]` | 운반 시작, 전 피어 | `경로=밧줄|캡슐추종` |
| `[소유권]` | 서버, 사망/부활 | `오너 X→Y` · `플레이어오브젝트유지` |

**줄머리 규칙:** `시체#<NetworkObjectId> 오너<OwnerClientId> 나<LocalClientId>`.
두 PC 로그에서 **같은 `시체#`**를 찾아 `권한=True`(권위)와 `권한=False`(원격)를 나란히 놓는 것이
이 계측의 사용법 전부다.

```bash
grep -E "소유권|리그물리|낙하속도|밧줄|자세도착|운반경로|래그돌대역폭" \
  "$USERPROFILE/AppData/LocalLow/DefaultCompany/undercover-team4-project/Player.log"
```

⚠ `[자세도착]`은 **권위에서 안 찍힌다**(보내는 쪽은 잴 것이 없다). 호스트가 모든 시체의 권위인
세션에서는 호스트 로그에 이 줄이 아예 없다 — 그때 네트워크를 보려면 **클라 로그가 필수**다.
직전 세션 로그는 같은 폴더의 `Player-prev.log`.
